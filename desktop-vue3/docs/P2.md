## 4. 旧库导入流程

```text
选择 .db
→ readonly 打开 + PRAGMA integrity_check
→ 读取 notes/tags/categories/runes/echoes 数量
→ 用 better-sqlite3 backup API 生成临时副本（包含 WAL）
→ 备份当前库到 <userData>/backups/
→ 关闭当前库，替换为目标文件
→ 重新打开 + migration v1
→ 校验 notes 数量
→ 失败则恢复备份
→ 清理临时文件
```

UI：设置 → 数据 → 导入旧库 / 备份 / 打开目录。

## 5. better-sqlite3 原生模块

本机没有 Visual Studio Build Tools，`electron-rebuild` 无法从源码编译。
项目使用 Electron ABI 的预编译包，脚本：

```powershell
pnpm rebuild:sqlite
```

`pnpm-workspace.yaml` 把 `better-sqlite3` 列入 `ignoredBuiltDependencies`，因此
`pnpm install` 不会尝试 `node-gyp` 编译；安装后必须执行上面的预编译脚本。

脚本会：

1. 读取 `electron` 的 `process.versions.modules`（当前 Electron 39 → ABI 140）；
2. 从 `registry.npmmirror.com` 下载对应 `better-sqlite3` 预编译包；
3. 解压到 `node_modules/better-sqlite3/build/Release/better_sqlite3.node`。

如果 `pnpm install` 后启动报 `Could not locate the bindings file`，先执行该脚本。
可用 `BETTER_SQLITE3_MIRROR` 环境变量替换镜像。

## 7. 已知限制

- 首页仍是静态笔记，P3 再接 `notes:list` 与真实 CRUD；
- 搜索仍是 `LIKE`，FTS 留给 P3；
- 未做标签清理、分类重命名、批量删除；
- 迁移只有 v1，后续 schema 变更继续追加 migration；
- 导入不自动合并重复 GUID，只做整库替换；
- 还没有 Vitest；本轮用 Electron + CDP 做集成冒烟；
- 导入失败回滚代码已实现，尚未做故障注入测试。
