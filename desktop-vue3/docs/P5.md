## 3. 架构约定（新代码必须遵守）

```text
渲染进程  →  services/ipc.ts  →  IPC_CHANNELS（shared）
主进程    →  controller/<模块>.ts  →  zod schema（shared/ipc/schemas.ts）
                                →  service/db/<模块>-repository.ts  →  better-sqlite3
状态      →  Pinia store（stores/*），视图只放 UI 状态
文案      →  i18n/locales/zh-CN.ts + en-US.ts，键必须成对
```

- 禁止在渲染进程直接 import Node/Electron 模块。
- 新通道一律进 `IPC_CHANNELS` 与 `INVOKE_CHANNELS` 两处，并补 zod schema。
- 数据库写入必须经过 repository，controller 只做 schema 校验与错误映射。

## 6. 结构重排（已完成）

`HomeView.vue` 从 1174 行降到 673 行，视图按 vue2 的分层思路拆成三块 + 一个纯函数模块：


边界约定：

- 子组件不持有笔记数据，只接收 props、发出语义事件（`select` / `update:selected` / `open-menu` / `create-note` / `batch-*`）。

- 侧栏的筛选状态由 HomeView 持有，子组件只发 `update:filter`，互斥清空逻辑收敛在一处。

## 7. 数据层与笔记操作夯实

### 7.1 schema 迁移 v2：查询索引

`notes` 列表默认按 `updated_at` 倒序、按 `category` 过滤、标签筛选走 `note_tags`、同步队列扫 `sync_log.synced`，
这些热路径原先只有 `category` / `dirty` 索引。v2 迁移补 7 个纯索引（`IF NOT EXISTS`，不改列定义，可重复执行）：

```text
idx_notes_updated_at   idx_notes_created_at   idx_notes_title
idx_note_tags_tag      idx_sync_log_synced    idx_sync_log_note
idx_tags_name_lower
```

### 7.2 同类目同名标题：对齐 vue2 的自动去重

v1 的唯一索引 `idx_notes_category_title_kb`（`title != 'Untitled'`）会在同类目同标题时抛 `SQLITE_CONSTRAINT`，
旧实现只会在 UI 上显示"保存失败"。现在把 vue2 `noteUniquenessService.js` 的语义搬进仓储层：

- `normalizeCategory()`：`''` / `'/'` / `'OFFLINE_ROOT_CATEGORY'` / `'/我的笔记/'` / `'/My Notes/'` 统一为 `/`；
- `normalizeTitle()`：去 `\u00a0`、折叠空白、空值回 `'Untitled'`；
- `generateUniqueTitle()`：同类目重名时追加 ` (2)`、` (3)`，扩展名保留（`a.md` → `a (2).md`）。

`create()` 与 `update()`（改标题时）都走这一层，等于在写入前收敛掉冲突，而不是等数据库报错。

### 7.3 写入原子性

- `create()`：`INSERT notes` + 重建 `note_tags` 放进同一个 `db.transaction`，不会留下"笔记写进去了但标签没写"的半成品；
- `update()`：`UPDATE notes` + 标签重建（当 `tags` 变更时）同样事务化；
- `remove()`：显式先 `DELETE FROM note_tags`，再删 `notes`，两件事在同一事务里——外键已有 `ON DELETE CASCADE`，这里是兜底（旧库若未开 `foreign_keys` 也不会留孤儿行）。

### 7.4 搜索 LIKE 转义

`list()` 的模糊查询把 `%` / `_` / `\` 转义后才拼进 `LIKE ... ESCAPE '\'`，
避免用户搜 `50%` 时把整库当成通配匹配。

### 7.5 文件夹（local_categories）

- `create()` 统一规范化路径，`parent` 由路径推导（`/a/b` → `/a`），不再信任调用方传入的 parent；
- `countNotes()` 提供真实笔记计数；
- **主进程**删除前校验非空，非空直接返回 `CATEGORY_NOT_EMPTY`，渲染层的提示不再是唯一防线；
- 根目录 `/` 不可删除。

### 7.6 数据一致性只读体检（已落地）

主进程新增 `service/db/diagnostics.ts` + `controller/diagnostics.ts`，通道 `controller/diagnostics/run`。
**只查询、只报告、绝不自动改库**——旧库长什么样必须先看清，否则"自动修复"会把数据问题变成数据事故。

检查项（每项返回 `count` 与最多 5 条样本）：

| kind | 含义 |
|---|---|
| `TAG_STRING_WITHOUT_LINKS` | `notes.tags` 有值但 `note_tags` 没有关系行 |
| `LINKS_WITHOUT_TAG_STRING` | 有关系行但兼容字段 `notes.tags` 为空 |
| `TAG_DRIFT` | 字符串集合与关系表集合不一致（逐笔记比对） |
| `DUPLICATE_TITLE` | 同类目下 `LOWER(TRIM(title))` 重复（`Untitled` 豁免） |
| `ORPHAN_LINKS` | `note_tags` 指向已删除的笔记或标签（外键未开时才会出现） |
| `UNREGISTERED_CATEGORY` | 笔记所在目录在 `local_categories` 里没有登记 |
| `UNUSED_TAG` | 无任何笔记引用的标签（清理候选，不是错误） |

渲染层入口在设置页「数据体检」卡片：显示健康标签、笔记/标签/关系/待同步计数、问题清单与样本。

### 7.7 SQL 冒烟校验（scripts/smoke-db.py）

本机起不了 Electron，`better-sqlite3` 是 Electron ABI 的二进制，`node` 直接 require 会报 `NODE_MODULE_VERSION` 不匹配。
所以用 Python 内建 `sqlite3`（3.49.1）从 `migrations.ts` 抽出建表/索引 SQL 真跑一遍：

```bash
cd desktop-vue3 && python3 scripts/smoke-db.py
# OK 表 15 张 / 索引 37 个 / 唯一约束与级联删除行为符合预期
```

断言内容：15 张表齐全、37 个索引存在（含 v2 新增）、同类目同名标题确实触发唯一约束（证明去重层是必需的）、
`Untitled` 豁免成立、删除笔记后 `note_tags` 无残留。**局限**：它验证 SQL 与约束行为，不验证 `better-sqlite3` 的 JS API 调用。

### 7.8 本地变更队列（outbox，已接线）

`sync_log` 之前只有表没有写入点，现在 `create/update/remove` 全部接入，仓储在
`electron/service/db/sync-log-repository.ts`。

**写入规则**

| 场景 | 行为 |
|---|---|
| `create()` | 同一事务内写 `create` 事件（`doc_guid = local_<uuid>`） |
| `update()` 且 `dirty = 1` | 写 `update`；若该笔记已有未同步的 `create`/`update`，**只刷新时间戳**，不叠行 |
| `update()` 且 `dirty = 0` | 不写（调用方已确认与服务端一致，如导入回填） |
| `remove()` 且 `doc_guid` 是 `local_` 前缀 | 不写（服务端从没见过这条笔记） |
| `remove()` 且 `doc_guid` 是服务端 guid | 写 `delete`，**`note_id = NULL`**，靠 `doc_guid` 定位 |

**为什么 delete 的 note_id 必须是 NULL**：`sync_log.note_id` 有 `ON DELETE CASCADE`，笔记一删，
引用它的日志会被连带清掉。这个坑在冒烟脚本里已经断言过：带 note_id 的 pending 行在删除后归零，
`note_id IS NULL` 的 delete 行存活。

**读取接口**

- 通道 `controller/sync/pending` → `{ summary, items }`，`summary` 是按动作的计数 + 最老时间戳；
- 设置页「数据」卡片显示待同步总数与「新增/修改/删除」拆分；
- `markSynced(ids)` 留给同步引擎在服务端确认后调用，**现在没有任何代码会调它**。

## 8. 功能批次 B1：@ 唤起快捷面板

### 8.1 事实澄清：面板本体在哪

vue2 的 `src/components/muya/Muya.vue` 里搜不到面板实现——因为**面板本身在 `libs-muya` 引擎里**
（`lib/ui/quickInsert/index.js`，795 行），vue2 只做了一件事：往 `options.quickInsertProvider` 里喂数据。

vue3 也一样：`packages/libs-muya/src/MuyaEditor.vue` 把 `props.options` 透传给 `new Muya(...)`，
所以复刻路径是「在 vue3 里构造同形状的 provider + 真实数据源」，不是重写面板。

### 8.2 数据链路

```text
SQLite runes / echoes
  → electron/service/db/library-repository.ts（list，按 sort_order + name）
  → controller/library.ts（controller/library/runes、controller/library/echoes）
  → frontend stores/library.ts（内存缓存，@ 打开时零 IPC）
  → frontend editor/quickInsert.ts（createQuickInsertProvider）
  → MuyaEditor :options="{ quickInsertProvider }"
  → 引擎 quickInsert 面板
```

### 8.3 item 形状（必须与 vue2 完全一致）

引擎对 item 的约定（`ui/quickInsert/index.js`）：

| 字段 | 作用 |
|---|---|
| `title()` / `subTitle()` | 函数而非字符串，渲染时调用 |
| `label` | 唯一键，`getItemElement` 用它定位 DOM；插入时**普通项**直接当 paragraph 类型用 |
| `icon` | 面板图标（data URI） |
| `searchText` | 过滤用，引擎按 includes 做子串匹配 |
| `meta.type` | 只有 `rune` / `echo` 走专用插入分支，其余走 `updateParagraph(label)` |

因此：
- 符文 item 带 `meta: { type:'rune', runeTemplateId, runeName, color, insertContent }`——`insertContent` 就是 SFC 模板，引擎据此解析 `inheritFromPrevious` 并生成 `data-rune-*` 占位 HTML；
- 回响 item 带 `meta: { type:'echo', echoName, color }`——引擎插入 `@名称{}()` 占位。
- 图标沿用 vue2 做法：色块 + 名称首字 SVG → base64 data URI（`TextEncoder` + `btoa`，中文/emoji 安全）。

### 8.4 触发与插入（引擎侧既有行为，未改动）

- 输入 `@` 且在行首或前面不是单词字符 → 打开面板（`contentState/inputCtrl.js#checkQuickInsert`）；
- 面板打开后按 `@后面的文本` 过滤（`getQuickInsertSearchText`）；
- 选择后按 `meta.type` 分派：`rune` → `insertRuneTemplate`（支持行内 @，会保留 @ 之前的文本）、`echo` → `insertEchoTemplate`；
- 分组顺序：引擎把「符文」「回响」两组优先排在默认项（标题/代码块/图表等）前面。

### 8.5 内置卡片播种（migration v3）

新库的 `runes` / `echoes` 是空表，面板会是空的。v3 迁移**仅在表为空时**播两条示例卡：

- `builtin-rune-counter`：点击自增的 SFC 符文（验证 `onValueChange` 链路）；
- `builtin-echo-demo`：最小 `anno_source` 回响。

`WHERE NOT EXISTS (SELECT 1 FROM runes)` 保证旧库导入后不会被覆盖。

## 9. 引擎去领域化：@ 面板只留接口层

### 9.1 现状诊断

`packages/libs-muya` 里，`core/` 本身是纯 JS（无 Vue 依赖），耦合只发生在两处：

1. `src/MuyaEditor.vue` 是 Vue 3 包装（peerDependencies `vue ^3.5`）——这是渲染壳，不是领域逻辑；
2. `core/ui/quickInsert/index.js` 把 **rune / echo 的插入语义写死在引擎里**：
   `createRunePlaceholderHtml`、`createEchoPlaceholderMarkup`、SFC `props.inheritFromPrevious` 解析、
   `data-rune-*` 占位协议——这些全是 Memocast 的领域约定，不在「Markdown 编辑器」的职责范围内。

### 9.2 这一步做了什么（只动引擎的接口，不动语义迁出）

新增 `options.quickInsertTypes` 注册表 + 两个原语：

```js
// 引擎侧（core/config/index.js）
MUYA_DEFAULT_OPTION.quickInsertTypes = {}

// 引擎侧（core/ui/quickInsert/index.js）
getTypeHandler(type)        // 先查 options.quickInsertTypes[type]，再回落到内置 rune/echo
getTypeHandlerContext()     // 给处理器的能力集：{ quickInsert, muya, contentState, block, replaceAtTrigger }
insertTextAtTrigger(text)   // 唯一承诺的插入原语：把 @query 换成文本，行内保留前缀，光标落末尾
```

`selectItem()` 改成注册表分派：

- 有处理器 → 调处理器；`echo` 保持「立即收面板」，其余走 finally 延迟收起；
- 没处理器 → 沿用原来的段落语义（`updateParagraph(item.label)`），标题/代码块/图表不受影响。

**关键点：rune / echo 变成「默认实现」而不是「唯一实现」**，app 注入同 key 的处理器即可覆盖。
这样领域逻辑可以分批搬走，不用一次性把引擎拆烂。

### 9.3 应用侧的 note 分支

`frontend/src/editor/insertHandlers.ts`：

```ts
export const quickInsertTypes = {
  note: (item, context) => context.replaceAtTrigger(`[[${item.meta.noteTitle}]]`),

```

`meta = { type: 'note', noteId, noteTitle }`，插入结果 `[[标题]]` 纯文本。

### 11.1 仓储层解耦 + 可执行测试（已完成）

问题：仓储代码 `import { getDatabase } from './database'`，而 `database.ts` 静态依赖
`better-sqlite3`（Electron ABI）和 `electron` —— 在纯 Node 里连模块都加载不了，

改法：

- `scripts/db-node-adapter.ts`：把 Node 22 内置 `node:sqlite` 包装成同一接口

- `scripts/db-test.ts`：内存库跑真实 migration + 真实仓储代码，**34 项断言**；

测试暴露出的三条既有设计（不是 bug，正好补齐认知）：

1. `sync_log` 的 `update` 会**折叠进 create**：本地笔记没同步前，连续编辑只刷时间戳，
   所以断言要检查「只有一行且 action 仍是 create」，而不是「有一行 update」；
2. 本地笔记（`doc_guid` 为 `local_` 前缀）删除时**不写 delete 行**：服务端本来就没有这条，

3. 体检 issue 的字段是 `kind / label / count / samples`，不是 `code`。

### 11.2 标签一致性治理（已完成）

口径先定死：**`notes.tags` 字符串是权威来源**（导出、同步、markdown 都以它为准），
`tags` + `note_tags` 只是派生索引。据此补了三处缺口：

1. **删除标签不清字符串**（真 bug）：原来 `tagsRepository.remove(id)` 只删了 tags / note_tags，
   `notes.tags` 里会留下"幽灵标签"，体检只能事后报 TAG_STRING_WITHOUT_LINKS。
   现在在一个事务里：摘掉字符串里的该标签 → 删关系 → 删标签本体；
2. **缺少重建入口**：新增 `tagsRepository.syncFromNotes()`，以字符串为准重算 note_tags（幂等，
   也可顺手补齐缺失的 tags 行），并在设置页「数据体检」卡片加了「重建标签索引」按钮，跑完自动重跑体检；
3. **不反向修字符串**：索引坏了重建即可，绝不改字符串 —— 避免"修复动作"变成第二个写入口。

新增 IPC：`tags.syncIndex`。

一个容易踩的坑（测试里写明了）：`TAG_DRIFT` 的定义是「字符串与关系表**两边都有但集合不同**」。
如果关系表一边全没了，会落到 `TAG_STRING_WITHOUT_LINKS`，不是 DRIFT。构造用例时别搞错。

### 11.3 备份 / 恢复完整闭环（已完成）

原来只有 `backupDatabase()`：能手动备份，恢复只能靠"导入旧库"那条路，缺回滚点、缺列表、缺策略。

拆成两层，纯粹为了能测：

| 文件 | 职责 | 能否 Node 测试 |
|---|---|---|
`service/db/backup-files.ts` | 命名规则、列表、保留策略（只用 fs） | 能 |
`service/db/backup.ts` | 立即备份、启动策略、校验、恢复与回滚（用 better-sqlite3 + Electron） | 不能 |

要点：

1. **命名白名单**：只认 `coolma-*` / `import-*` / `pre-restore-*`，用户自己丢进 `backups/` 的 `.db` 永远不会被清理；
2. **保留策略**：手动/自动备份保留最新 7 份，`pre-restore` 回滚点与 `import` 临时件不受裁剪；
3. **时间排序用 mtime**：Linux 上 `birthtime` 常不可靠（备份文件只写一次，mtime 就是创建时间），
   第一版用 birthtime 导致列表顺序乱，测试直接抓出来了；
4. **启动自动备份**：`autoBackupIfDue()`，距最近一份手动备份超过 24h 才做，避免每次启动堆一份；
   在 `preload` 里 fire-and-forget，不阻塞窗口；
5. **恢复顺序**（与 legacy 导入同构）：
   校验候选（`integrity_check` + 有 notes 表）→ 打 `pre-restore` 回滚点 →
   关库、清 WAL/SHM → 用 better-sqlite3 的 `backup()` 落一份干净副本再覆盖 →
   重新 init（会跑 migration 把旧 schema 升上来）→ 核对笔记数 →
   任何一步失败：回滚到 `pre-restore` 并重新 init；
6. **恢复要二次确认**：设置页弹 `ElMessageBox` 明确告知"将覆盖当前库、已自动打回滚点"。

新增 IPC：`database.backups`、`database.restore`。设置页新增备份列表（文件名/大小/时间/类型）与逐条恢复按钮。

### 10.13b B5 渲染验证：又抓到两个真 bug

B5（符文/回响真正渲染成卡片）跑通了，代价是又挖出两个"编译完全看不出"的引擎 bug。

**bug 1：符文卡片其实没挂上，是 harness 的模板太素**

第一次断言失败时日志里已经有 `mounted vm`，但查不到卡片元素。原因不是引擎，是 harness
用的模板是 `<template><div/></template>`，卡片渲染出来当然是个空 div。换成带标记的
`<button class="coolma-rune-demo">` 之后立刻通过——**这条记在验证脚本里，别再被自己误导**。

顺带确认了渲染链路完整：

```
markdown: <div data-rune-name="counter" data-rune-id="…" data-rune-node-id="…" data-rune-value="">counter</div>
→ parser 认成 HTML 块
→ renderRunes() → mountRuneVueHosts() → RuneRenderer(propsData) → $mount → host.appendChild(vm.$el)
→ DOM 里出现 .coolma-rune-demo
```

**bug 2（真 bug，影响线上功能）：回响卡片的宿主属性名对不上**

现象：回响永远只显示 `@xxx` 圆胶囊，`anno_source` 里写的自定义 HTML 从来没生效。

链路排查到最后一行属性列表：

```text
["class","spellcheck","title","contenteditable","data-start","data-end","data-raw",
 "data-echoname","data-echoid","data-echonodeid","data-echoinline"]   ← 全是小写连写
```

引擎侧读的是 `host.dataset.echoNodeId` / 选择器 `[data-echo-node-id]`，
而 snabbdom 的 dataset 模块把驼峰键**直接拼**成属性名（`echoNodeId` → `data-echonodeid`），
于是 `renderEchoPlaceholders()` 一个宿主都扫不到，永远走"胶囊兜底"。

两处修：

1. `snabbdom.js`：不用自带 dataset 模块，自己实现一份，统一把驼峰转 kebab-case
   （`toAttrName()`），并处理 create/update/destroy。
2. `renderInlines/echoAnno.js`：在 `attrs` 里**显式**再写一份 kebab-case 属性
   （`data-echo-name` / `data-echo-id` / `data-echo-node-id` / `data-echo-value` / `data-echo-inline`），
   这样即使换打包器、换 snabbdom 版本，宿主也一定找得到。

**还有一个接口约定差点写错**：`anno_source` 里的 `render()` 必须返回 **HTML 字符串**；
返回 `{ html: '…' }` 这种对象，运行时只会拿到空字符串，卡片静默变空——文档里写清楚。

**最终运行级验证 19 项全过**（多出来的 4 项）：插件安装、符文占位落 DOM、符文卡片挂载、
回响卡渲染、回响卡拿到 value。回归：`typecheck 0`、`build 0（33.15s）`、L1 13 项全过。

### 10.13c 取值回写：回响补齐了，符文留一个已知缺口

**回响多了一个接口。** 引擎里符文的回写（`updateRunePlaceholderValue`）是插件提供的，
回响一直没有对应能力——卡片里改值没法落回 markdown。按对称补上：

```ts
// plugins-muya-echo/src/index.ts
runtimeEditor.updateEchoPlaceholderValue = ({ echoId, value }) => {
  // 找到 @name{echoId: '…', value: '…'}() 里匹配 echoId 的那个 token，替换 value 后 setMarkdown
}
```

验证结果：`value: '' → '42'` 写回 markdown 成功，重新渲染卡片显示 `42`。

**符文留一个缺口，不装作通过。** 符文回写本身是通的（`data-rune-value="" → "7"`），
但它是通过 `editor.setMarkdown()` 实现的，而 markdown **再解析**时：

```text
写入: <div data-rune-name="counter" … data-rune-value="7">7</div>
解析: Lexer 判定为 html token → createHtmlBlock → figure + 代码预览（标签变成转义文本）
结果: [data-rune-node-id] 宿主消失，卡片不再挂载
```

也就是说，**同一个符文 div，第一次插入时是可挂载宿主，保存后再打开就变成一块代码**。
这不只是回写的副作用，是"笔记重启后符文卡片全掉"的严重隐患。根因在导出/解析往返：

- 导出端：html 块只有单个 `\n` 收尾，marked 的 html 规则要 `\n{2,}` 或文件尾；
- 解析端：即便判成 html token，也会走 `createHtmlBlock`，而符文需要的是"行内 html_tag 挂宿主"。

两条路都试过了（导出补空行、段落里单块 html 归位），结果是把它推得更深一层成 html 块，
卡片照样不回。**所以没有强行改，只把现状记成缺口**，标注在验证脚本里：

```text
SKIP 符文卡片显示新值（已知缺口：setMarkdown 往返后 div 被判成 html 块）
```

正确修法（下一批做）：给 `createHtmlBlock` 加一条分支——内容是单个 `div[data-rune-node-id]`
时，不走代码预览，直接产出一个可挂载的宿主块，并让 `renderRunes()` 能扫到它。这在 vue2 引擎里
本来就是既有行为，对齐即可。

### 10.13d 符文往返缺口：三套修法都试过，全部退回

结论先写：**没修成。** 三个方向都试了，每个都能在某一环看到进展，但一改就打坏插入链路，
最后全部回退，只留下一条无害的补强。这不是"差不多能行"，是"还没找到对的层"。

| 尝试 | 做法 | 结果 |
|---|---|---|
| ① 导出补空行 | html 块 `\n\n` 收尾，让 marked 认成 html token | token 确实是 html 了，但 `createHtmlBlock` 把它塞进代码预览，宿主照样没有 |
| ② 段落归位 | 单块 html 段落强制转 html 块 | 更糟：被推深一层，仍是代码块 |
| ③ 行内通道 + 渲染还原 | 解析留行内 html、`renderLeafBlock` 直接输出带 dataset 的真实 div | 预览层能出 div，但插入链路连带崩了：卡片不挂、回写返回 false |

**留下的唯一改动**：`renderInlines/htmlTag.js` 里把 `data-rune-*` 从 `attrs` 搬进 `dataset`。
这条是必要的——挂载逻辑读 `host.dataset.runeNodeId`，属性只在 `attrs` 里时会被判"缺字段"跳过。
它单独不足以修好，但方向正确，先留着。

**为什么三次都撞墙（值得记下来的判断）**：符文在 markdown 里是"html 块"，
而引擎里 html 块设计上就是**代码 + 预览**，不是"可交互宿主"。想把两者塞进同一个类型，
每次都得在某一层写特例，特例又会污染插入路径。

**所以正确的修法不是打补丁，而是提类型**：给 contentState 加一个真正的 `rune` 块类型
（`functionType: 'rune'`），它自带 `runeId/nodeId/value` 字段、渲染成宿主、序列化时输出那段
`<div data-rune-*>`。这样解析、渲染、回写、挂载四条链路各有明确归属，不用互相迁就。
这属于结构性改动，**需要你点头再动**，不适合我自行决定。

### 10.13e 符文往返缺口修好了：根因是属性被白名单挡掉

上一节说三套修法都撞墙，结论是"要提类型"。真动手之后发现，**真正卡住的不是块类型，

**真实链路（一层层剥）**：

1. 回写后 `setMarkdown` → Lexer 判成 html token → `createHtmlBlock` → 块是 `pre/html + div/html`

   `data-rune-*` 一个都没放行 → attrs 全空 → dataset 空 → 挂载被判"缺字段"跳过。

| 文件 | 改动 |
|---|---|
| `parser/utils.js` | 白名单放行 `data-rune-*` / `data-echo-*` |
| `utils/importMarkdown.js` | 单块符文 div → `functionType: 'rune'` 段落块（不走 html 块） |
| `renderInlines/htmlTag.js` | `data-rune-*` 从 attrs 搬进 dataset（挂载逻辑读 dataset） |
| `parser/render/renderBlock/renderLeafBlock.js` | 上一轮留下的兜底分支（保留） |

### 11.17 光标同步（已完成）

补 vue2 双编辑器切换时的光标传递：切到源码模式带着 Muya 光标进 Monaco，切回来带着 Monaco 光标回 Muya。

- **口径纠错（关键）**：原版 Muya 的 `getCursor/setCursor` 收发的是 **0-based `{ line, ch }`**，Monaco `Position` 是 **1-based**。vue2 的 `Muya.getCursorPosition` 按 1-based 判合法（`line >= 1`、`ch >= 1`），等于把 0-based 当 1-based 用——切回去光标会整体错一行。vue3 不抄这处偏差，统一走 `frontend/src/utils/cursor.ts` 换算（`muyaCursorToPosition` 加 1 / `positionToMuyaCursor` 减 1，下界钳零）。
- **引擎接口**：`MuyaEditor` 暴露 `getCursor / setCursor / setMarkdownWithCursor`；`core/index.d.ts` 补 `getCursor`、`setCursor`、`setMarkdown(markdown, cursor?, isRenderCursor?)` 三处签名（实现本来就有，缺的只是对外）。
- **Monaco 侧**：`SourceEditor` 补 `getCursor / setCursor`（getPosition；setPosition 前限幅 lineNumber ∈ [1, lineCount]、column ≤ getLineMaxColumn，防 "Illegal value" 抛错；落位后 `revealPositionInCenterIfOutsideViewport` + focus），对齐 vue2 `Monaco.vue`。
- **切换逻辑**：`EditorPane.toggleSourceMode()` 双向传递——去源码模式前读 Muya 光标转 Monaco 位置，`nextTick` 后落位（Monaco 是 v-if 新挂载）；回富文本前读 Monaco 位置转引擎光标。内容仍走同一个 `contentProxy`，不双写。
- **测试**：L3 运行级 34→41 项——引擎带 cursor 的 `setMarkdown` 往返一致、越界 cursor 不抛错、换算四条（加1/减1/钳零/往返/空兜底）；tsc + typecheck + build + db-test(101) 全绿。
- **未做（报备）**：按笔记记忆上次光标（vue2 没有这层，属增强，下个大周期）。
