# P3 真实数据与笔记 CRUD

> 状态：P3 核心完成。首页已从静态示例切到 SQLite 真实数据；重命名/移动/标签编辑留到下一步。

## 1. 数据链路

```text
HomeView
  └─ useNotesStore (Pinia)
       └─ frontend/src/services/ipc.ts
            └─ controller/notes|categories|tags
                 └─ notes-repository / categories-repository / tags-repository
                      └─ better-sqlite3
```

`frontend/src/stores/notes.ts` 负责：

- 一次加载 notes / categories / tags；
- 打开笔记时按 id 拉取完整 `content`；
- 新建、保存、删除后同步列表与 `total`；
- 避免快速切换时旧请求覆盖新笔记（请求序号）。

`HomeView` 只保留 UI 状态：索引模式、筛选条件、当前笔记、自动保存计时器。

## 2. 列表与索引

- `notes:list` 一次取最近 5000 篇，保证 1000 篇测试库可以完整筛选；
- 文件夹：按 `notes.category` 聚合，`categories:list` 只补零计数项；
- 标签：按 `notes.tags` 聚合，`tags:list` 只补零计数项，零使用标签不显示；
- 时间：按 `updatedAt`（回退 `createdAt`）分为今天/昨天/本周(近 7 天)/更早；
- 三种模式继续写 `localStorage['coolma.indexMode']`，刷新/重启保留。

`NoteSummary` 只带摘要，不载入正文；当前笔记通过 `notes:get` 拉完整内容。

## 3. 搜索

搜索使用后端 `notes:list` 的 `query`：

```sql
(title LIKE ? OR content LIKE ?)
```

前端 250ms 防抖，结果再叠加文件夹/标签/时间筛选。正文命中不会因为摘要截断而丢失。
目前是 LIKE，FTS5 留到后续。

## 4. 新建 / 编辑 / 自动保存 / 删除

- 新建：`notes:create`，默认标题“无标题”，内容 `# 无标题`；
- 编辑：Muya `v-model` → 700ms 防抖 → `notes:update`；
- 切走/卸载：先 `flushSave()` 再加载下一篇，避免丢最后一段输入；
- 标题：从正文第一个 `# 标题` 派生，同步更新列表标题；
- 删除：`ElMessageBox` 确认 → `notes:remove` → 选中下一篇；
- 空库：显示“还没有笔记”，新建/删除最后一篇都不报错。

Muya 编辑器保持**单实例**，切换笔记只 `setMarkdown`，不再按 `:key` 重挂载。
原因是 Muya 会替换挂载节点，频繁 remount 会让 Vue 的 vnode 与真实 DOM 脱节。

## 7. 已知限制

- 列表一次渲染 1000+ DOM，后续需要虚拟滚动；
- 5000 是硬上限，超过需要分页；
- 没有重命名、移动、标签/分类编辑 UI；
- 没有未保存草稿/崩溃恢复；
- 搜索是 LIKE，不是 FTS5；
- 时间“本周”按最近 7 天实现，不是自然周。
