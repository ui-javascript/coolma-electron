## P0

### P0-1 `get-app-path` 语义漂移 —— 状态：已完成

- **证据**：原版 `api.js:332` 返回 `app.getAppPath()`（应用根目录）；Tauri `bridge.js:73` 原先返回 `app_data_path`（数据目录）
- **使用方**：`AiDoubaoDrawer.vue:93`、`fullscreenOverlay.vue:281`、`genericMicroAppIpcBridge.js`（microApp 资源根路径）
- **影响**：AI 抽屉 / microApp 用该路径拼资源（`_plugins/<id>/dist/index.html`），现在指到 `%LOCALAPPDATA%\cn.coolma.tauri`，找不到应用自带资源
- **方案**：Rust 新增 `app_root_path` 命令（release 取 `current_exe()` 所在目录；dev 取 `src-tauri` 的上一级即打包目录），bridge 的 `get-app-path` 切到该命令
- **验收**：`ipcRenderer.invoke('get-app-path')` 返回 exe 所在目录；dev 模式返回 `desktop-vue2-tauri`
- **落地**（`2d85931b` 之后）：`main.rs` 新增 `app_root_path` + `app_root_from_exe` 纯函数与 4 个单测；`bridge.js:73` 换命令。注意：原版 dev 返回仓库根、Tauri dev 返回打包目录，属构建方式差异，已在单测里钉住

## P1

### P1-1 数据库写放大（sql.js 全量快照） —— 状态：待决策（用户暂缓，先记下）

- **证据**：`src/desktop/database/index.js:264-278` 每条写命令都 `db.export()` 整库序列化 + 整文件落盘；原版为 better-sqlite3 增量写
- **现状**：当前库 5.8 MB，等于每改一篇笔记写 5.8 MB；库变大后内存与写放大会同步放大
- **方案 A（架构级）**：Rust 侧 `rusqlite` 代理，前端保留 `db:*` 通道语义，SQL 走 Rust（接近原版形态）
- **方案 B（过渡）**：仍用 sql.js，但写入合批（如 300ms debounce）+ 退出前强制 flush，只缓解不根治
- **验收**：单次编辑不再整库写盘；库 >50 MB 时编辑不卡；异常退出最多丢合批窗口内的写入
- **当前决定**：暂不动代码，等拍板选 A 还是 B

### P1-2 safeStorage 遗留密文迁移 —— 状态：已完成

- **证据**：原版 `electron-main.js:67-90` 有 CryptoJS 旧版解密分支；Tauri `credential.js` 原先只认 `keyring:` 引用，其余一律返回空串
- **排查补充（比原判断更严重）**：本机真实老库 `%APPDATA%\coolma\memocast.db` 里那行 `api_key_encrypted` 版本号是 **2**，但内容不是引用，而是 Electron safeStorage 的 `v10` 密文 —— 即"AES-256-GCM，密钥由 DPAPI 包裹后存在 `Local State` 的 `os_crypt.encrypted_key`"。所以迁过来的老库 **v1 和 v2 都读不出来**，不只是 v1
- **方案**：两种历史格式都就地解出，解出来即用；下次保存配置时自然升级成 keyring 引用
  - v1：`crypto-js` 按原版机器派生密钥（`包名|版本|userData|platform|arch|hostname` 做 SHA256）；seed 各段都可能变，故由 Rust 出候选密钥列表逐个试解，命中要求明文是可打印 ASCII 且 ≥8 字符
  - v2：Rust `dpapi_unprotect` 做 DPAPI 解封（`CryptUnprotectData`）拿 32 字节 AES 密钥，前端用 WebCrypto `AES-GCM` 解 `v10`/`v11` 密文
- **落地**：`credential.rs` 新增 `legacy_data_dir` / `legacy_key_secrets` / `dpapi_unprotect`；`Cargo.toml` 加 windows 专用的 `windows-sys`（DPAPI 绑定）；`credential.js` 重写读取路径并加会话内明文缓存
- **验证**：Rust `cargo test --ignored` 用真实 `Local State` 解封出 32 字节密钥（`dpapi_unwraps_electron_safe_storage_key` ok）；真实密文经 DPAPI + WebCrypto 解出 35 字符、以 `sk-` 开头的可打印明文；Jest 新增 7 条（v1 往返、错密钥跳过、全错返空、明文形态、v10/v11 切分、DPAPI 前缀剥离）
- **已知边界**：用户若已卸载 Electron 版、`Local State` 随目录被删，DPAPI 密钥随之丢失，只能重填；v1 的 seed 含历史版本号，跨版本的老密文可能已无法解开（原版同样如此）

### P1-3 `file://` 资源覆盖面 —— 状态：已完成（收窄式对齐）

- **证据**：原版 `electron-main.js:3932` 用 `interceptFileProtocol('file')` 透传整个本地磁盘；Tauri `wiz_resources.rs` 原先只服务 `kb/doc/name` 三段缓存
- **实际用到 `file://` 的地方**（全仓只有两处，且都是内置微应用入口）：`AiDoubaoDrawer.vue:77`、`fullscreenOverlay.vue:169` 拼 `_plugins/<id>/dist/index.html`
- **方案**：`coolma-resource` 增加 `local/abs/<percent-encoded 绝对路径>` 路由，只放行三种根：应用数据目录、应用根目录（exe 所在目录）、系统临时目录；其余 403，不做任意路径透传
- **落地**：`wiz_resources.rs` 新增 `local_file` / `within_roots` / `local_request_path` / `static_type`，规范化后校验白名单、拒绝目录穿越、32 MB 上限；html/js/css 不下发 sandbox CSP（否则微应用脚本会被拦），其余沿用原版 CSP；本地路由带 `Access-Control-Allow-Origin: *` 以支持跨源加载
- **前端**：`wizResources.js` 新增 `localFileUrl()`（`file://` 与本地裸路径都归一成协议地址，非 Tauri 环境原样返回），两处微应用入口改用它；`fullscreenOverlay.vue` 的 `toFileUrl` 随之删除
- **验收**：`cargo test` 新增 7 条用例（解码、拒绝错误前缀、根内放行、根外拒绝、目录穿越拒绝、目录本身拒绝、html 类型）；白名单外路径返回 403
- **已知边界**：笔记正文里若有人手写 `file:///D:/x.png`，仍不会被 Muya 渲染（我们的图片一律走上传播转为资源 URL）；这条属于原版"全盘放开"的残留能力，按"不做任意路径透传"的取舍放弃

### P2-1 崩溃提示缺失 —— 状态：已完成

- **证据**：原版 `electron-main.js:3863` 用 `electron-unhandled` 弹窗 + 一键开 GitHub issue；Tauri 原先只有 `logs/<年>/<月>/main.log`
- **方案**：运行标记 + 崩溃报告。启动写 `run-marker.json`（含启动时间、pid），正常退出（`RunEvent::Exit`）清掉；下次启动发现标记还在即判定上次没正常走完，落 `last-crash.json` 并在日志打一行 warn
- **落地**：新增 `src-tauri/src/crash.rs`（`begin` / `end` / `last_crash_report`，含 3 条单测）；`logging.rs` 抽出 `log_file_path` 供复用；`main()` 改为 `build().run()` 以便在 `RunEvent::Exit` 清标记；前端新增 `src/desktop/crash.js`，启动时读一次报告并弹 `Notify`（带「查看日志」按钮 → `open_log_file`），读完即删避免反复提示
- **验收**：实机跑通——首次启动 marker 落盘 48 字节；`Stop-Process -Force` 强杀后 marker 仍在；重启后日志出现 `[warn] 检测到上次异常退出（2026-11-21 19:52:40 启动的进程）`，且 `last-crash.json` 已被前端消费删除
